# Rubbish-cleaner 项目文档

> 一个轻量、便捷、易操作的 Windows 流氓软件检测与残留清理工具
> 版本：v0.1（规划稿） | 最后更新：2026-10-23

---

## 1. 项目概述

**Rubbish-cleaner** 是一款面向 Windows 普通用户的系统清理工具，核心解决三个问题：

1. **检测**流氓软件（开机自启动、后台常驻、无界面、无图标、无托盘）
2. **协助删除**（调用自带卸载程序 + 强制结束顽固进程）
3. **残留清理**（卸载后的残留文件 + 孤儿注册表项清除）

设计原则：**越轻量、越便捷、越易操作越好**。

---

## 2. 项目背景与痛点

### 2.1 流氓软件的核心特征

| 特征 | 说明 |
|------|------|
| 开机自启动 | 通过注册表 Run 键、启动文件夹、服务、计划任务等方式常驻 |
| 后台常驻、不在任务栏 | 无可见窗口、无任务栏按钮，用户"看不见"却持续占用资源 |
| 不在桌面/开始菜单创建图标 | 用户无法通过常规入口找到并卸载它 |
| 部分不在系统托盘显示 | 彻底隐藏自身存在感 |

### 2.2 卸载残留问题

大部分软件调用自带 uninstaller 卸载后，仍会留下大量残留：

- **文件残留**：`Program Files`、`ProgramData`、`%AppData%`、`%LocalAppData%` 中的目录
- **注册表残留**：`Uninstall` 键、`Software` 键、`Run` 键、文件关联、COM 组件等孤儿项
- **驱动/服务残留**：已卸载但服务仍注册、驱动文件仍占用

这些残留不仅占用磁盘，还可能导致新装软件冲突、系统变慢。

---

## 3. 目标与定位

- **目标用户**：不懂技术的普通 Windows 用户（小白优先）
- **产品定位**：轻量绿色工具，对标 Everything 的速度 + Geek Uninstaller 的一体化清理
- **非目标**：不做系统优化全家桶、不做弹窗广告拦截、不常驻后台（用完即走）

## 4. 参考项目分析

### 4.1 Everything

| 维度 | 借鉴点 |
|------|--------|
| 核心技术 | 直接解析 NTFS **MFT**（主文件表）建索引，全盘几十万文件**秒级**完成 |
| 关键优势 | 传统 `Directory.GetFiles()` 递归遍历完全无法达到此速度 |
| 落地方式 | P/Invoke `DeviceIoControl` 打开卷句柄 `\\.\C:` 读取 `$MFT` |

> 结论：残留文件扫描必须采用 MFT 直读，否则性能无法接受。

### 4.2 Geek Uninstaller

| 维度 | 借鉴点 |
|------|--------|
| 产品形态 | 约 3MB 单文件绿色版，免安装 |
| 核心能力 | "强制卸载 + 残留扫描 + 注册表清理"一条龙 |
| 交互风格 | 克制、专业，不做夸张的"电脑体检"式营销 |

> 结论：形态上做绿色单文件，能力上做"卸载 + 残留"闭环。

## 5. 技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 语言/框架 | C# + WPF | 轻量、部署简单，`ListBox` 虚拟化性能好，适合展示大量文件 |
| 目标框架 | .NET 8 | 成熟稳定，支持自包含单文件发布 |
| 部署方式 | Self-Contained 单文件 | 免安装绿色版，无需运行时 |
| 权限 | 启动时 UAC 提权 | 检测 HKLM Run、服务、计划任务需管理员权限 |
| 搜索引擎 | 直读 NTFS MFT | Everything 同款，秒级全盘索引 |
| 平台 | Windows 10/11 x64 | 目标平台 |

> 备选否决记录：WinUI 3 需 WindowsAppSDK 运行时、偏臃肿，且存在已知的 E_CLASSNOTREG COM 部署坑；WinForms 控件老旧，大量文件列表虚拟化不如 WPF。

## 6. 系统架构

```
┌─────────────────────────────────────────────────────┐
│                  RubbishCleaner.App (WPF UI)         │
│        启动提权 / 软件列表 / 评分展示 / 操作确认        │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│               RubbishCleaner.Core (核心引擎)          │
│                                                      │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐        │
│  │  检测引擎   │ │  卸载引擎   │ │  清理引擎   │        │
│  │ Detection  │ │ Uninstall  │ │  Cleanup   │        │
│  └────────────┘ └────────────┘ └────────────┘        │
│  ┌────────────┐ ┌────────────┐                        │
│  │  绝对确认表  │ │  NTFS MFT   │                       │

└──────────────────────────────────────────────────────┘
```

**三层职责**：

- **检测引擎**：枚举自启动项、判断进程可见性、计算流氓评分
- **卸载引擎**：聚合已装软件、调用自带卸载程序、强制结束进程
- **清理引擎**：卸载后残留扫描（MFT）、孤儿注册表项清理

## 7. 核心功能设计

### 7.1 检测引擎（MVP 重点）

#### 7.1.1 自启动检测点位

| 类别 | 具体位置 | 版本 |
|------|---------|------|
| 注册表 Run | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` / `RunOnce` | v0.1 |
| 注册表 Run | `HKLM\Software\Microsoft\Windows\CurrentVersion\Run` / `RunOnce` | v0.1 |
| WOW64 兼容层 | `...\WOW6432Node\...\Run` | v0.1 |
| 启动文件夹 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` | v0.1 |
| 启动文件夹 | `%ProgramData%\Microsoft\Windows\Start Menu\Programs\Startup` | v0.1 |
| Windows 服务 | `HKLM\SYSTEM\CurrentControlSet\Services`（`Start=0x02`，排除微软签名） | v0.1 |
| 计划任务 | `C:\Windows\System32\Tasks`（需管理员，经 Task Scheduler COM） | v0.1 |
| Winlogon 劫持 | `Winlogon\Shell`、`Userinit`、`Notify` | v0.2 |
| AppInit_DLLs | `...\Windows NT\CurrentVersion\Windows` | v0.2 |
| IFEO 映像劫持 | `...\Image File Execution Options` | v0.2 |
| 浏览器扩展/劫持 | 浏览器主页、搜索引擎、扩展 | v0.3 |

#### 7.1.2 后台常驻无界面判断

对每个进程执行三条 Win32 API 判断：

1. **无可见窗口**：`EnumWindows` + `GetWindowThreadProcessId` + `IsWindowVisible`
2. **不在任务栏**：`GetWindowLong(GWL_EXSTYLE)` 含 `WS_EX_TOOLWINDOW`、无标题、有隐藏 owner
3. **不在托盘**：枚举 `Shell_TrayWnd` 子窗口的 `ToolbarWindow32`（MVP 先作"疑似"加分项，托盘枚举无公开 API，可靠性一般）

#### 7.1.3 流氓评分模型

将"是/否"判断转化为**加权评分**，避免误杀：

| 特征 | 分值 |
|------|------|
| 开机自启动 | +30 |
| 常驻进程无界面 | +25 |
| 无桌面图标 | +15 |
| 无开始菜单项 | +15 |
| 无托盘图标 | +15 |
| 数字签名缺失/发行商未知 | +10 |
| 进程名伪装系统名（如 `svch0st`） | +10 |

**分级**：

| 分数区间 | 等级 | 呈现 |
|---------|------|------|
| 0–40 | 正常 | 绿色 |
| 41–70 | 疑似 | 黄色 |
| 71–100 | 高风险 | 红色 |

#### 7.1.4 绝对确认表（Trust Table）

评分之外设置**硬判定兜底**，避免误杀正规软件、漏判已知流氓：

- **白名单（可信）**：微软签名、系统组件、知名厂商（如腾讯、字节、微软等）签名 → 直接标"安全"，不参与高风险评分
- **黑名单（已知流氓）**：内置已知流氓特征库（进程名模式、安装路径、特定注册表键）→ 直接标"高风险"
- **存储与更新**：本地 JSON 可编辑；v0.2 起支持在线更新特征库

> 判定逻辑：白名单命中 → 安全；黑名单命中 → 高风险；均未命中 → 走启发式评分。

### 7.2 卸载引擎（v0.2 规划）

- 聚合 `Uninstall` 注册表键（HKCU/HKLM，含 WOW6432Node）生成软件列表
- 支持调用自带卸载程序（`UninstallString`）
- 强制结束占用进程，删除顽固文件（`MoveFileEx` + `MOVEFILE_DELAY_UNTIL_REBOOT`）

### 7.3 清理引擎（v0.3 规划）

- **残留文件扫描**：卸载前记录快照 / 按软件名特征扫描常见位置（`Program Files`、`ProgramData`、`%AppData%`、`%LocalAppData%`），采用 MFT 直读加速
- **注册表清理**：扫描并清除关联的 `Software` 键、`Uninstall` 键、文件关联、COM 组件等孤儿项

## 8. 关键技术与难点

| 难点 | 说明 | 方案 |
|------|------|------|
| MFT 直读 | 需管理员权限 + 卷句柄 | `CreateFile("\\\\.\\C:")` + `DeviceIoControl` 读 `$MFT` |
| 权限提权 | HKLM/服务/计划任务需管理员 | 启动时 UAC 提权（app.manifest `requireAdministrator`） |
| 顽固文件删除 | 文件占用、权限拒绝 | 结束进程 → `MoveFileEx(DELAY_UNTIL_REBOOT)` 重启删除 |
| 托盘图标枚举 | 无公开 API | MVP 降级为"疑似"加分项，不硬判定 |
| 计划任务读取 | 需管理员 + COM | `TaskScheduler` COM 接口 |
| 评分误杀 | 启发式可能误判正规软件 | 绝对确认表白名单兜底 + 分级呈现由用户抉择 |

## 11. 风险与合规

- **误删风险**：删除前必须二次确认，绝对确认表白名单兜底，默认不自动删除、只展示
- **权限风险**：提权后操作需谨慎，所有删除走系统回收站或可恢复机制
- **合规**：仅检测和协助用户手动清理，不做静默删除、不修改系统关键组件
- **稳定性**：读写注册表/文件前做好备份与回滚提示
