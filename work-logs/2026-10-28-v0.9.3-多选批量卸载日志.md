# v0.9.3 修复日志：已安装软件多选批量卸载

> 日期：2026-10-28　标签：`v0.9.3`　前置：v0.9.2

## 1. 报告现象

「多选删除的软件点击『卸载已选的软件』之后，只会卸载第一个；当第一个的卸载进程结束，
不会接着启动第二个选中软件的卸载进程。」

## 2. 根因（两个，叠加）

1. **列表不能多选**：`MainWindow.xaml` 的软件 `ListBox` 没有设置 `SelectionMode`，WPF 默认 `Single`。
   用户 Ctrl/Shift 点选时只是移动单选光标，看着像选中多条，实际只有一条。
2. **卸载命令只处理单个条目**：`UninstallSelectedAsync` 第一行就是 `var item = Selected;`，
   之后整段都是单条目流程（预检查 → 确认 → 执行 → 等待 → 提示），没有任何循环。
   所以哪怕真拿到多条，也只会跑一条。

## 3. 修复

| 文件 | 改动 |

| `src/RubbishCleaner.App/Views/MainWindow.xaml` | 软件列表 `SelectionMode="Extended"`；新增 `SelectionChanged="OnAppSelectionChanged"`；按钮 `Content` 改绑 `Apps.UninstallButtonText` |

| `tests/RubbishCleaner.App.Tests/AppsBatchUninstallTests.cs`（新增） | 7 项：串行、跳过、取消、确认文案、单选旧行为、失败继续 |

### 3.1 为什么必须串行

卸载程序几乎都带界面、且很多要弹 UAC。并发启动多个会互相抢焦点、抢文件锁，
用户也不知道该点哪个窗口；有的卸载器还会互相 kill。所以严格「启动 → `WaitForExit` → 下一个」。
`UninstallExecutor` 本身就有 15 分钟超时保护，一个卡住不会永久挂起（会报「超时未结束」并继续下一个）。

### 3.2 为什么只确认一次

逐条确认在批量场景下是灾难（3 个软件弹 3 次框，还容易点错）。
改成确认框里**列出全部命令**，用户一次看清要跑什么再决定；取消就一个都不执行。

## 4. 验证

- `dotnet build`：0 警告 0 错误；
- `scripts/test.ps1`：**690 passed / 0 failed**（Core 486 + App 204，新增 7 项）；
- `tools/RubbishCleaner.UiProbe`：全部通过（含 `SelectionMode=Extended`）；
- 关键断言：选中 3 个 → 执行器被调用 3 次、**并发峰值 1**、命令顺序与选择顺序一致；
  第 1 个失败时第 2 个仍然执行；坏条目被跳过但其余继续；取消确认时执行 0 次。

## 5. 未做

- 没有做「卸载队列可视化」（进度列表/取消剩余）：状态栏已显示第 i/n 个，够用；要做得先设计取消语义
  （中断 `WaitForExit` 可能留下半卸载状态），风险大于收益。
- 双击条目仍是「按当前选中集合卸载」；如果用户多选后双击，等价于点按钮（同样会先确认）。
