## 1. 为什么需要引导

v0.8 之前的标题栏版本号是**硬编码字面量** `v0.6.0`。发布到 0.8 之后，界面上写着 0.6.0——
这不是笔误，是一个会随版本增长必然变成假信息的结构缺陷。顺手修掉：改绑程序集版本，
`csproj` 的 `<Version>` 成为唯一真源。

更要紧的是「风险分」这三个字。它是若干条规则加分得到的 0–100 分，
**不是病毒判定，也不是查杀结果**，但普通用户看到「疑似」会直接理解成「已确认是病毒」。
引导要做的就是把这层误解提前拆掉。

## 2. 引导的设计约束

| 约束 | 理由 |
|------|------|
| 用覆盖层，不开独立窗口 | `App.xaml` 没设 `ShutdownMode`，WPF 默认 `OnLastWindowClose`；多开一个窗口就要自己管生命周期，覆盖层不引入这个风险 |
| 文案里的数字必须来自 `ScoringWeights.Default` | 测试 `GuideCopy_QuotesTheRealWeightsAndThresholds` 逐字钉住 8 个数字；改权重时文案必须跟着改，否则测试红 |
| 只讲界面上真实存在的东西 | 应用内**不能**手工改判定（特征库只能经「设置 → 特征库在线更新」更新），所以不写「你可以把程序标记为安全」 |
| 标记只在「看完并关闭」后落盘 | 中途崩溃/断电不会把引导吞掉；旧版本升级上来的 `settings.json` 没有该字段，反序列化为 `false`，会再看一次——这是有意的，v0.8 才第一次解释风险分 |

## 4. 独立审计发现并修掉的 2 处**不实文案**

文案写完不等于写对。做了一轮逐条对照源码的独立审计（11 条断言），
**9 条为真、2 条为假**，两条都已修正：

1. **「程序当前没在运行时，相关项标记为「不适用」」——过度概括。**
   实际只有「没有可见窗口」带 `!isRunning`（`RiskScorer.cs:82`）；
   「没有桌面图标」`(:86)`/「没有开始菜单」`(:90)` 只按 `serviceOnly || orphan` 判，
   「没有数字签名」`(:97)` 只按 `orphan` 判。已改为逐项点名。
   顺带补上「已失效的启动项本身记 0 分，但它仍会按「存在自启动项」拿到 30 分」——
   这是原文漏掉的真实语义（`RiskScorer.cs:29`、`:106`）。
2. **「启动项备份可在「备份历史」页回滚」——指向了错误的页面。**
   启动项备份写在 `%LocalAppData%\RubbishCleaner\backups`（`MainViewModel.BackupDirectory`），
   而「备份历史」页只枚举 `registry-backups` 下 `orphan-*` 前缀的条目（残留注册表清理）。
   两者不是同一个目录。已改为「备份放在「打开备份目录」里，双击就能还原；
   残留注册表清理的备份可在「备份历史」页一键回滚」。

另有 3 处措辞收紧（非事实错误）：标题「会覆盖分数」→「会覆盖结论」
（被改写的是结论，`RiskScorer.cs:125` 返回的 `total` 本身不变）、
「删除一律走回收站」限定为「删除的文件和目录」（注册表项没有回收站，走 .reg 备份 + 删值/删键）。

两条修正都用测试钉住，防止日后回退。

## 5. 真机验证（实测，非推断）

前 5 次尝试在 `run_code` 里直接跑 UI Automation 脚本**全部超时且零产物**。
用分段诊断定位：`Add-Type` 加载 UIA/Drawing 程序集、`Start-Process` 拉起 GUI、
重定向、sleep、`Stop-Process -Force` **全部正常**——问题出在工具输出捕获与 UIA 调用的组合。
改法：把探针写成独立 `.ps1`，用 `Start-Process powershell.exe -File` **脱离父进程**执行，
结果只写文件，父进程轮询读取。此后两次运行均一次通过。

实测结果（删掉 `%ProgramData%\RubbishCleaner\settings.json` 制造真正的首次运行）：

| 引导标题 | `先花一分钟看懂「风险分」` 渲染成功 |
| 文案文本节点 | 168 个 |
| 点「知道了，开始使用」 | 引导消失，`guideStillVisible=False` |
