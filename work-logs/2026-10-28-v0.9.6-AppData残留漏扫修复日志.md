# v0.9.6 修复日志：AppData 残留漏扫

> 日期：2026-10-28　标签：`v0.9.6`　前置：v0.9.5

## 1. 用户反馈

「卸载残留留在 c 盘 user 下的 appdata 里面也会有一些残留没被扫到。」

## 2. 四个原因（叠在一起）

### 2.1 没有 InstallLocation 就整条跳过（最致命）

`UninstallSnapshotStore.TakeSnapshot` 在 `InstallLocation` 缺失时返回 null，`CaptureBefore` 因此返回 false；
卸载后 `ScanAfterAsync` 找不到快照 → **完全不做定向扫描**。

而按用户安装的软件（Electron/Squirrel、绿色安装器等）大量不写 `InstallLocation`——它们的残留恰恰就在
`%LocalAppData%` 下。这条链路断了，怎么扫都扫不到。

### 2.2 扫描器自己也早退

`UninstallResidueScanner.ScanAsync` 在 `InstallLocation` 为空时直接 return，连"按名字找目录"都不做。

### 2.3 只看第一层

`AppendNameMatchedDirectoriesAsync` 只枚举 `Directory.EnumerateDirectories(root)` 的直接子目录。
`%LocalAppData%\Programs\<App>`、`%AppData%\<厂商>\<产品>`、`%ProgramData%\<厂商>\<产品>`
这些两层形态全部漏掉。

### 2.4 文案与实现不符

Evidence 里写着「已安装软件列表中没有任何条目认领该目录」，但代码里根本没查 `InstalledApps`。
用户如果把软件又装回去，照样会看到这条"残留"。

## 3. 修复

| 文件 | 改动 |
|---|---|
| `Core/Residue/UninstallSnapshotStore.cs` | 新增 `TakeNameOnlySnapshot(app)`：只有软件名/厂商/卸载命令，无文件清单 |
| `App/ViewModels/UninstallResidueCoordinator.cs` | `TakeSnapshot ?? TakeNameOnlySnapshot`，没有安装目录也留快照 |
| `Core/Residue/UninstallResidueScanner.cs` | 去掉早退：无安装位置时跳过第 1/2 步、仍做第 3 步；按层枚举（`SafeEnumerateDirectories` 带深度与预算）；新增 `IsClaimedByInstalledApp` |
| `Core/Residue/UninstallResidueModels.cs` | `MaxDepth`（默认 2）、`MaxDirectoriesPerRoot`（默认 4000） |
| `Core/RegistryCleanup/OrphanCleaner.cs` | 新增 `RegistryBackupWriter` 委托注入（默认仍是 `RegistryKeyBackupWriter.Write`） |

边界控制：

- 只对 `AppData\Local` / `AppData\Roaming` / `AppData\LocalLow` / `ProgramData` 深挖一层；
  其余根（Program Files、用户主目录）仍只看一层——再深就会把 Documents/Desktop 翻个底朝天。
- 每个根最多枚举 4000 个子目录；不进入重解析点；深挖时不进 `Temp` / `Packages` / `Microsoft` / `Windows`。
- 命中外层目录后不再把它内部的同名子目录重复报一遍。

## 4. 顺带修的测试隐患（重要）

跑测试时发现 `OrphanCleanerTests` 的 4 条 `Execute_*` 突然红了，报「跳过：备份失败（键不存在：…）」。
排查结论：这些测试注入的只是"键是否存在"，**备份仍然走真实注册表**，
所以它们一直在偷偷依赖本机恰好装着的某个产品（`{09CC399B-…}`）。用户今天用本工具批量卸载了软件，
那个产品的 Uninstall 键没了，测试就红了——**测试不该依赖真实环境**。

修法：`OrphanCleaner` 增加 `RegistryBackupWriter` 委托（第 6 个可选参数），测试注入假备份器；
`Execute_BackupFails_DoesNotDelete` 改用 `BackupFails` 开关，不再用 `Z:\` 这种"靠环境失败"的写法。

## 5. 验证

- `dotnet build`：0 警告 0 错误；
- `scripts/test.ps1`：**711 passed / 0 failed**（Core 498 + App 213）；
- 新增断言：无安装位置仍能按名字找到数据目录、两层厂商目录能找到、`MaxDepth=1` 时不深挖、
  外层命中不重复报内层、被已安装软件认领的目录不报、协调者无安装位置也留快照。

## 6. 仍未做

- **通用**残留扫描（残留扫描页）仍然只信硬痕迹（目录里有卸载程序 / 失效启动项），
  不会因为"名字像某个已卸软件"就报 AppData 目录——那是 93% 误报的老坑。
  本版修好的是"卸载后定向扫描"这条确定性链路。若要覆盖"用别的方式卸载、工具没看到"的情况，
  需要另外设计（例如按已卸载软件的历史清单做检查，属于新功能）。
