# 2026-10-24 开发日志 —— v0.2.0 卸载引擎

## 目标

产品文档里 v0.2 是"软件列表 + 协助卸载"。这是价值最大的一块，也是风险最高的一块——
**要执行来自注册表的命令**。

## 做了什么

### 1. 软件列表：520 → 114

三处 `Uninstall` 键（HKLM 64 位 / WOW6432Node / HKCU）读完是 520 条，但真软件只有 114 个。

不过滤的话，工具直接不可用——用户会被 400 多个系统补丁和运行库淹没。

过滤规则：

| 条件 | 本机数量 | 理由 |
|------|---------|------|
| `SystemComponent=1` | 376 | 系统组件不是"用户装的软件" |
| 无 `UninstallString` | 116 | 对卸载工具没意义 |
| `NoRemove=1` / 有 `ParentKeyName` | 62 | 明确不可卸载 / 子组件 |

### 2. 脏数据清洗

本机「明日之后」这条目的 `DisplayName` 是这样的：

```
明日之后 羮翶 琢 Ѐ 琢 Ѐ 쳐恓ǹ 翻  ...
```

第三方安装器把二进制垃圾直接写进了注册表字符串。

清洗策略是**截断**而不是过滤：垃圾从某处开始整段污染，后面的没价值，
而前面的「明日之后」恰恰有用。截断点判定：控制字符、私用区字符、孤立代理项。

### 3. 卸载前三道检查

卸载要执行注册表里的命令，而注册表**任何程序都能写**，必须当不可信输入。

| 检查 | 拒绝条件 |
|------|---------|
| 命令存在 | 无 `UninstallString` |
| 系统工具拦截 | 主程序是 `cmd`/`powershell`/`reg`/`sc`/`mshta` 等 |
| 程序存在 | 卸载器文件不存在 |

第二条是关键：防的是"注册表被篡改后借本工具执行任意命令"。

### 4. 执行策略刻意做"薄"

`UninstallExecutor` 只做三件事：启动进程、等待、报告结果。

- **不自行拼接静默参数**——各软件参数五花八门（`/S` `/silent` `/qn` `--silent`），
  猜错会卸载异常甚至卡死。要用静默就用注册表现成的 `QuietUninstallString`。
- **不强制删除任何文件**——卸载由软件自己的安装器负责，这是产品合规底线。
- 15 分钟超时（Adobe 系卸载很慢，但不能无限等）。

### 5. UI 拆成两个页签

原来所有东西堆在一个列表里。现在：

| 页签 | 回答的问题 |
|------|-----------|
| 启动项检测 | 什么在开机时偷偷跑？ |
| 已安装软件 | 我装了什么？怎么卸掉？ |

这两个关注点混在一起会互相干扰——"风险评分"和"软件管理"根本不是一回事。

## 踩的坑

### 坑 1：一刀切拦截误杀了 7 个 NVIDIA 软件

加完"禁止系统工具"规则后，7 个 NVIDIA 全被拦。但它们的卸载命令是：

```
RunDll32.EXE "…\InstallerCore\NVI2.DLL",UninstallPackage Display.Driver
```

这是 NVIDIA **官方标准**的卸载方式，完全合法。我把 rundll32 和 cmd 归成了一类。

重新想了一遍：**rundll32 本身不可疑，可疑的是"加载任意 DLL"**。

放行条件：
1. DLL 是绝对路径；
2. DLL 真实存在；
3. DLL 不在系统目录（系统目录的 DLL 不该被第三方当卸载器）。

### 坑 2：加完例外，NVIDIA 还是被拦——但这次是对的

验证时发现仍然被拦，我一度以为例外没生效。

查下来：`C:\Program Files\NVIDIA Corporation\Installer2\InstallerCore` **目录根本不存在**，
`NVI2.DLL` 全盘都搜不到。

所以这 7 条是**卸载器已失效的残留条目**，拦截是**正确**的。是我一开始判断错了。

顺带在列表里加了「卸载程序缺失」标记，用户不用点了才发现。

> 这条值得记：**验证例外规则生效与否，不能只看"是否放行"，
> 还要确认被拒的那一方是否本来就该拒。**

### 坑 3：rundll32 路径解析出来是空串

例外逻辑写好后，测试仍失败。打印中间结果才看清：

```
command = "C:\Windows\System32\rundll32.exe" "C:\Temp\NVI2.DLL",UninstallPackage ...
exeEnd = 29  →  rest = [" "C:\Temp\NVI2.DLL",...]
```

用 `IndexOf(".exe")` 切口，切出来的 `rest` 开头那个引号是 **exe 路径的收尾引号**，
按"引号包裹"解析立刻匹配到空串。

修复：先整体剥离 exe 部分（复用 `TryExtractExecutable`），再解析参数。

### 坑 4：检查顺序让提示信息误导

把"绝对路径校验"放在了"系统工具拦截"前面，结果 `cmd.exe /c del ...`
报的是"卸载程序路径不是绝对路径"——完全掩盖了真正原因。

**安全拦截必须最先执行。** 用户看到的提示才有意义。

## 未能在本轮验证的部分

**没有真正执行一次卸载。** 原因：本机 114 个软件都是有主的，卸载任何一个都会破坏用户环境。
真实卸载涉及删除用户数据，不能拿用户的机器做实验。

已通过的其他保障：
- 卸载检查逻辑有 20 项单元测试覆盖（含 5 种系统工具形态、4 种 rundll32 情形）
- 执行器只测"拒绝路径"（命令为空、卸载器不存在），不实际调起第三方程序

**建议用户自己用一个不重要的软件试一次**，确认卸载流程符合预期。
