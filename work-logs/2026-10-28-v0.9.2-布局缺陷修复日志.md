# v0.9.2 修复日志：两个真机布局缺陷

> 日期：2026-10-28　标签：`v0.9.2`　前置：v0.9.1

## 1. 报告现象（用户真机截图）

1. 「已安装软件」页签：中间一大块空白白面板，顶部隐约有列头，右上/右侧一个很高的粉色「卸载选中的软件」框；
   有 115 个软件却一条都看不到。
2. 「设置」页签：滚不到底，「关于软件」卡片下面被裁掉，看不到。

## 2. 根因

### 2.1 已安装软件：越界 Grid.Row 被夹到最后一行

```xml
<!-- 修复前 -->
<Grid Margin="16">
  <Grid.RowDefinitions>
    <RowDefinition Height="Auto" />   <!-- 0 工具条 -->
    <RowDefinition Height="*" />      <!-- 1 列表 -->
  </Grid.RowDefinitions>
  ...
  <Border Grid.Row="2" ...>            <!-- 2 底部操作条：行根本不存在 -->
```

WPF 不会为越界索引自动加行，而是**夹到最后一行**。用 PowerShell + WPF 做了最小复现（`work-logs/tmp/grid-probe.ps1`）：
两行定义的 Grid 里把子元素设为 `Grid.Row=2`，布局后实测 `top=20, height=280`（即落在 row 1 并占满剩余高度）。
这条白色 Card 在视觉树里排在 ListBox 之后 → 直接盖住列表，同时按钮被拉伸成“很高的粉色框”。

该缺陷自 **v0.2.0** 就存在（`git show 2cb51f6:...MainWindow.xaml` 确认当时也只有 2 行定义），
因为没有任何 UI 级测试，一直没人发现。

### 2.2 设置页：没有滚动容器

设置页 Grid 的 4 行全是 `Height="Auto"`，外层 TabItem 没有 ScrollViewer，窗口高度不够时后两张卡直接裁掉。

## 3. 修复

1. 已安装软件页补第三行 `<RowDefinition Height="Auto" />`。
2. 设置页内容整块套 `<ScrollViewer VerticalScrollBarVisibility="Auto" HorizontalScrollBarVisibility="Disabled">`。
3. **不做“全部页签都包一层”**：列表类页签靠 `*` 行撑满，套 ScrollViewer 会让内层 ListBox 拿到无限高度、
   失去内部滚动与虚拟化 —— 有反向测试钉住这条边界。

## 4. 新增回归测试（7 项，`tests/RubbishCleaner.App.Tests/XamlLayoutTests.cs`）

不启动窗口、不需要管理员，直接解析 `MainWindow.xaml`：

| 测试 | 作用 |
|---|---|
| `EveryGridChild_StaysWithinDeclaredRowsAndColumns` | 任意 Grid 子元素 `Grid.Row/Column`（含 Span）不越界——这类 bug 的通用守卫 |
| `InstalledAppsTab_HasRoomForBottomActionBar` | 已安装页至少 3 行，且存在 `Grid.Row=2` 的底部条 |
| `SettingsTab_ContentIsScrollable` | 设置页内容在 ScrollViewer 内且 `VerticalScrollBarVisibility=Auto`，且仍只有一个 Grid |
| `ListBackedTabs_AreNotWrappedInScrollViewer`（4 个 Theory） | 启动项/已安装/残留/备份历史不得被 ScrollViewer 包裹 |

实现细节：XAML 通过 `<None Link="Xaml\MainWindow.xaml" CopyToOutputDirectory="PreserveNewest">` 复制到测试输出目录，
不依赖“从 bin 往上找仓库根”。
