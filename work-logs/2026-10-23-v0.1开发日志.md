## 关键决策

1. **用 .NET 10 SDK 构建 net8.0 目标** —— 产品文档指定 .NET 8，SDK 向后兼容。
2. **计划任务用 XML 解析而非 TaskScheduler COM** —— 守住零第三方依赖。
3. **黑名单优先于白名单** —— 防"放进白名单目录即洗白"。
4. **不开启 PublishTrimmed** —— WPF 与裁剪不兼容，会在运行期崩溃。
5. **引入 `tools/RubbishCleaner.Smoke`** —— WPF 主程序要 UAC，无法自动化验证；
   用无界面工具跑真实引擎，才可能在开发期发现真问题（事实证明发现了 5 个）。

## 踩坑记录

### 坑 1：WinVerifyTrust 目录签名直接让进程崩溃

```
Fatal error. System.AccessViolationException
   at AuthenticodeVerifier.WinVerifyTrust(...)
```

原因：`WINTRUST_CATALOG_INFO.pcCatalogContext` 我按字面理解传了
`CryptCATAdminEnumCatalogFromHash` 返回的枚举句柄，实际上该字段类型是
`PCATALOG_INFO`，`WinVerifyTrust` 会把它当结构体指针解引用 → 读非法内存。

**做法**：写一个最小复现工程，逐步打印每一步的中间结果，最后确认正确组合是
`pcCatalogContext = NULL` + `hMemberFile = 已打开的文件句柄`。

教训：**P/Invoke 结构体字段类型必须查文档，不能靠字段名猜。**

### 坑 2：`NotApplicable` 标记不生效

加了"纯服务型不参与无窗口/无图标判定"，但分数没变。原因是
`ScoreItem.Contribution => Hit ? Weight : 0` 只看了 `Hit`，
而"不适用"的项 `Hit` 仍然是 `true`。

教训：**加语义标记时，要同时检查所有消费该标记的地方。**

### 坑 3：PowerShell 脚本中文乱码

Windows PowerShell 5.1 读无 BOM 的 UTF-8 脚本会按 ANSI 解码，中文全乱，
连字符串引号都配对失败。所有 `.ps1` 必须存为 **UTF-8 with BOM**。

### 坑 4：系统组件"无签名"其实是目录签名

`X509Certificate.CreateFromSignedFile` 只看内嵌签名。Windows 大量系统二进制
（`spoolsv.exe`、`SearchIndexer.exe`）走 catalog 签名，会被误判成未签名，
进而把微软服务推成高风险。必须走 `WinVerifyTrust`。
