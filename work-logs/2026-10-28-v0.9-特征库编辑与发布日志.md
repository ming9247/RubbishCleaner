## 4. 踩坑记录

1. **`git add` 报 `failed to encode ... from UTF-8-BOM to UTF-8`**：本机 git 2.55 的 iconv 没有 `UTF-8-BOM` 别名，
   而 `.gitattributes` 里 `*.ps1` 用了 `working-tree-encoding=UTF-8-BOM` → 任何 `.ps1` 都无法入库。
   改为把 BOM 作为普通内容存进 blob（检出仍是 BOM + CRLF），并验证 `git checkout-index` 往返字节一致。
2. **`edit` 工具写回 `.ps1` 会丢 BOM**：改完必须用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($true))` 补 BOM，
   并用 `Parser::ParseFile` 复检 `parseErrors=0`（否则 PS 5.1 按 ANSI 解码中文会直接语法错）。
3. **`signature-info.json` 的 `sizeBytes` 记录的是签名前大小**（签名会追加签名块，实测差 1942 B）：
   已在 `sign.ps1` 里改为记录前重新 `Get-Item`（提交 `6f7f277`）。
4. **`git push` 连不上 github.com:443**：本机 Git 不走系统代理（WinINET 有 `127.0.0.1:7897`，git 没有），
   而 `Invoke-WebRequest` / `gh` 走系统代理所以正常。解决：`git -c http.proxy=http://127.0.0.1:7897 push ...`。
   该代理设置**不写进仓库配置**，只在本机命令行临时指定。

## 5. 已知限制（未变）

- 自签名证书**不解决发布者身份可信**，SmartScreen 仍提示「未知发布者」；正式对外分发需 OV/EV 或 Azure Trusted Signing（技术设计文档 §11.3）。
- 签名不检查吊销状态（`WTD_REVOKE_NONE`），离线吊销查询可用性未解决。
- 4 条黑名单条目（暴风集团、快压、风行、软媒）带误报风险，若收到误伤反馈可降级为更精确的 `name` 规则。
