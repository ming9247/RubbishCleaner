# v0.7.0 工作日志 —— 特征库在线更新 + 备份清理

日期：2026-10-25
版本：v0.7.0
基线：614 passed / 0 failed / 0 warnings（Core 439 + App 175）

## 本轮目标

用户从 v0.7 候选里挑了两件：

1. **特征库在线更新**——项目传到 GitHub 后，用户启用联网即可从 git 拉取最新特征库；
2. **备份历史清理**——backups 目录随使用增长，保留最近 N 个，其余移入回收站。

## 核心约定（延续此前各版）

- **联网必须 opt-in**：AppSettings.EnableNetworking 默认 false。这不只是按钮禁用——
  CheckUpdateAsync / UpdateNowAsync 公开方法入口都有 CanUseNetwork 守卫
  （测试发现直调能绕过按钮 CanExecute，已修）。
- **只写用户层**（ADR-008）：在线更新只写 %ProgramData%\RubbishCleaner\trust-table.json，
  内置表与程序目录表永不覆盖；删除用户层文件即回退到旧特征库。
- **永不硬删除**：备份清理走 RecycleBin.MoveToRecycleBin，与 v0.6 回滚同一约定。
- **备份历史页形态不变**：仍是"只读 + 回滚"；清理入口放在新设置页，
  BackupHistoryViewModel 的反射锁死测试原样通过。

## 本轮踩坑

1. **直调绕过按钮守卫**：CheckUpdateAsync 只靠命令 CanExecute 挡联网，测试直调时
   真的发起了请求。修法：公开方法入口加 CanUseNetwork 守卫，按钮只是 UI 层的第二道提示。
2. **IBackupHistoryStore 加成员会破坏所有假实现**：接口上新增方法后
   BackupHistoryViewModelTests.FakeStore 编译失败（预期内），补实现即可；
   Core 测试没有该接口的假实现，不受影响。
3. **AppSettings 路径注入**：测试需要把 settings.json 重定向到临时目录，
   给 AppSettings 加了不参与序列化的 SettingsPathOverride（Load 显式传路径时会把
   返回实例指回同一路径，保证"存-读-再存"闭环）。

## 遗留

- ~~DefaultGitHubRawUrl 占位~~：**已解决**（后续 commit `572de7e` 已把它指向正式仓库
  `ming9247/RubbishCleaner` 的 `main` 分支；实测该 raw URL 返回 HTTP 200 / 2383 字节 / `version=2`）。
  流程不变：设置页勾选「启用联网」→「检查更新」→ 有新版则「立即更新」→ 重启生效。

  写盘分支只在单测里覆盖过；要验证写盘需先抬高远程版本号或手工构造更高版本的文件。
