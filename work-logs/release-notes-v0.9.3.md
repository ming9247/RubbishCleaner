## RubbishCleaner v0.9.3

修一个真机反馈：**多选软件点「卸载选中的软件」，只卸第一个，结束后不会接着卸第二个**。

### 两个原因（叠加）

1. **列表根本没开多选**：`ListBox.SelectionMode` 默认 `Single`，Ctrl/Shift 点按并不能真的选中多条；
2. **卸载命令只读单个 `Selected`**，没有任何批量循环。

### 修好之后的行为

| 项 | 说明 |
|---|---|
| 多选 | Ctrl / Shift 点选，按钮文案变成「卸载选中的 3 个软件」 |
| 严格串行 | 逐个「启动 → 等它结束 → 再启动下一个」，同一时刻只有一个卸载进程（卸载器带界面又要弹 UAC，并发会互相打架） |
| 坏条目不拖垮整批 | 没有卸载命令 / 预检查不通过的**只跳过它自己**，其余照常卸载；跳过的原因在确认框和汇总里点名 |
| 只确认一次 | 确认框列出这一批每个软件的真实卸载命令；取消则一个都不执行 |
| 进度可见 | 状态栏显示「正在等待「X」的卸载程序结束（第 2/3 个）…」，结束后一次汇总（成功/失败/跳过） |

> 单个卸载仍有 15 分钟超时保护：卡住会报「超时未结束」，然后继续下一个，不会整批挂死。

### 测试

新增 `AppsBatchUninstallTests`（7 项，执行器与枚举全部注入，**绝不真启动卸载程序**）：
选中 3 个时命令执行 3 次且**并发峰值 = 1**、顺序与选择一致；坏条目跳过而其余继续；取消确认零执行；
单选用旧行为；某个失败也继续下一个。真实 WPF 布局探针追加断言 `ListBox.SelectionMode = Extended`。

总计 **690 passed / 0 failed**（Core 486 + App 204）。
