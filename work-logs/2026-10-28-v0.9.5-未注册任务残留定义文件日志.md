# v0.9.5 修复日志：任务计划程序里找不到的任务

> 日期：2026-10-28　标签：`v0.9.5`　前置：v0.9.4

## 1. 现象（用户真机）

「启动项残留里这一项，我用命令在 cmd 或者 powershell 中运行都显示找不到该程序，任务计划里翻遍列表也没找到。」

项名：`\OneDrive Standalone Update Task-S-1-5-21-2339563914-684473125-2472836793-500`

## 2. 根因

任务计划程序有两份"事实"：

| 位置 | 作用 |
|---|---|
| `C:\Windows\System32\Tasks\<name>`（XML 文件） | 只是**定义文件** |
| `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache\Tree\<name>` | **是否注册**（UI 是否列出它） |

我们的 `ScheduledTaskSource` 是按 v0.2 的设计**枚举文件**的（ADR-002：不引入 TaskScheduler COM）。
这本身没错——但"文件存在"不等于"任务注册着"。OneDrive 升级时删掉了注册项却没删 XML，
于是出现「有文件、没注册」的孤儿：

- 任务计划程序里：不存在 → 用户翻不到；
- `schtasks /Delete /TN ...`：报「找不到该程序」；
- 我们的 v0.9.4 指引却让他去执行这条必然失败的命令。

## 3. 修复

1. 新增 `src/RubbishCleaner.Core/Detection/ScheduledTaskRegistration.cs`：
   读 `TaskCache\Tree` 判断任务名是否还注册。**三态**：`true` / `false` / `null`（非管理员读不到 → 无权判断，
   不能瞎断言"未注册"）。
2. `ManualFixAdvisor.For(entry, isTaskRegistered)`：探测可注入（单测确定性覆盖三条分支）。`TaskGuide`：
   - 未注册 → 标题「残留的计划任务定义文件（任务计划程序里已不存在）」，
     `Command = del /f /q "<C:\Windows\System32\Tasks\<name>>"`，`Target = TaskDefinitionFile`；
   - 已注册 → 原来的 `schtasks /Delete`；
   - 无权判断 → 保留 `schtasks`，`CommandHint` 追加「若找不到，说明只剩定义文件，可直接删除：<路径>」。
3. App：`ManualFixItem` 为 `TaskDefinitionFile` 提供按钮「在文件夹中选中该定义文件」+ 三步提示；
   `MainViewModel` 对这类项提示"需要管理员权限"（它落在 `System32\Tasks` 下）。

## 4. 验证

- `dotnet build`：0 警告 0 错误；
- `scripts/test.ps1`：**703 passed / 0 failed**（Core 492 + App 211）；
- 新增断言：已注册→schtasks、未注册→del+文件路径+TaskDefinitionFile、无权判断→schtasks+文件兜底提示、
  以及 App 侧"选中定义文件并提示管理员权限"。

## 5. 已知限制 / 后续

- 反向孤儿（注册表有、文件没了）目前扫不出来：枚举入口是文件系统。要覆盖需要同时读 `TaskCache\Tree` 枚举任务名，
  属于检测口径变更，下一版单独评估（会影响"失效启动项"的判定范围）。
- `TaskCache` 只有在管理员下才可读，因此本工具必须提权运行——它本来就是 `requireAdministrator`，
  但若用户用非提权方式启动，会退化成"无权判断"分支（给两种出路，不会误导）。
